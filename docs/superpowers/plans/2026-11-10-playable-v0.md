# Playable v0: Spec and Plan

> **For agentic workers:** use superpowers:subagent-driven-development with a **lighter cadence**: one implementer per task, an independent review after P2 and after P5 (not after every task), then a playtest by Travis.

**Goal:** the first version of Latentia a person can actually play, in a desktop browser and on a phone. It runs from the title screen to an end card in about 10–15 minutes, on the finished engine, with placeholder art.

**Why now:** the engine and simulator are done, and the fun is unproven. Travis decided on 2026-11-10 to get a real playable version running before more balance work.

**Stack (from the design bible):**
- Phaser **4.2.x** (npm `latest`), TypeScript strict, Vite.
- A new private workspace package, `packages/game`.
- It imports **only** `@latentia/engine`'s public API. It never imports engine internals, and it never imports `@latentia/sim`.

## The v0 player journey
1. **Title.** New Game or Continue (Continue appears only when a save exists).
2. **Lab.** One line from the professor, then pick a starter: Sagelet (Reasoning), Blitzr (Speed) or Forkling (Open).
3. **Rival fight.** Kip picks the counter-type starter and fights you one on one at L5 (Ruling 146).
   - This teaches commanding: the orchestrator's move menu, the intent preview and the temperature dial.
   - Losing restarts the fight. There is no game over.
4. **Walk to the trailhead.** A tiny overworld: lab exterior → path → Deprecated Forest trailhead. Grid movement, one sign, one NPC line.
5. **First wild model.** A wild **Tokenibble** (L3) battle triggers at the trailhead.
6. **Distill.** You win, then choose **Spin up** (recommended) or **Graft** (Rulings 145 and 147).
   - Spin up: Tokenibble joins at L3 as your first subagent, with 1 active card slot.
   - Graft: its signature becomes a grid piece on your orchestrator.
7. **Card tutorial** (spin-up path only). Teach Tokenibble one example card from a choice of 3 presets, shown as `IF … THEN …`. This sets its deck.
8. **First forest trainer.** Bootcamp Grad, with an Autopilot deck. It is a split-control battle: your subagent acts from its deck, and CardTrace "why" popups explain each action.
9. **End card.** "Thanks for playing v0", with a short stats summary (turns, cards fired, distill choice) and a link back to the title.

**Explicitly not in v0:** the grid editor UI (grids are preset), Record Example, Dry Run, XP and levelling, evolution, puzzles, Patchwater, the gym, ghosts, audio, the writing pass, and final art.

## Technical spec
- **Rendering**
  - Internal resolution **320×180**, `pixelArt: true`, integer scaling only.
  - **Landscape** (desktop or wide): the game screen is centred and letterboxed.
  - **Portrait** (phones): the 320×180 screen is integer-scaled at the top, with a **DS-style bottom band** below it for touch controls and battle menus (bible §"battle UI that works in landscape and portrait").
  - The layout re-computes on resize and orientation change.
- **Input.** One abstraction maps keyboard (arrows/WASD, Z/Enter = A, X/Esc = B), touch (bottom-band D-pad, A, B and menu buttons) and pointer taps on menu items to the same actions.
- **Text.** A crisp pixel bitmap font: generate a small 5×7 or 6×8 bitmap font texture in code, or use an OFL-licensed pixel font with its licence file committed. All text goes through one typewriter dialogue box component. Body text has no anti-aliased system font.
- **Battle scene.** It is driven entirely by the engine API: `validateSetup` → `createBattle` → `getIntents` → `submitRound` → events.
  - The UI plays the **event stream back in order** with simple tweens: MoveUsed text, Damage bar drain, status icon, faint, swap.
  - It shows each foe's intent before you commit, a move menu with context costs, the temperature dial (T0–T4), HP and context bars, and a "why?" popup that renders the CardTrace in plain words.
  - It must handle every event type the engine emits, with at least a text fallback.
  - Win or lose resolves into the flow.
- **Overworld.** One small tile map, authored as a Tiled-compatible JSON or a typed array in code. 16×16 tiles, grid movement, collision, an interact action, encounter and trainer triggers, and a camera that follows the player.
- **Art (placeholders).**
  - Use the Fable starter sprites from branch `art/style-test` (`art/style-test/*-idle-sheet.png`). Copy them into `packages/game/public/assets`, and credit the source in the README.
  - Every other creature gets a generated placeholder: a type-coloured rounded silhouette with an initial, drawn in code from the Endesga 32 palette.
  - Tiles are generated palette swatches with simple patterns.
- **Save.** localStorage key `latentia.save.v0` stores a versioned JSON (`schemaVersion: 1`) at each journey step: starter, distill choice, Tokenibble's deck, and current step. Continue resumes at the step's start. Mid-battle resume is out of v0.
- **Content.** Battles use engine content: species, moves and the fixed L5/L3 levels above. Trainer decks are defined in `packages/game/src/content/trainers.ts`. Every battle setup must pass `validateSetup` in a unit test.
- **Quality bar.**
  - No console errors.
  - 60 fps on a mid-range phone.
  - Battle turns resolve visibly in ≤ 1.5 s at 1× speed, with a 2× toggle.
  - No softlocks: every menu has a B/back path, and the losing path restarts the fight.
- **Tests.**
  - Vitest unit tests for the pure logic: the flow state machine, the event-to-UI-step mapper, input mapping and save versioning.
  - One Playwright smoke test (Chromium) that boots, starts a new game, picks a starter, and plays the rival battle to a result via an automation hook. The hook is `window.__latentia` and is exposed only in test or dev builds.
  - The engine's existing tests stay green.

## Tasks
- **P1: Shell.**
  - `packages/game` with Vite, Phaser 4 and TS.
  - The scaling and layout manager (landscape and portrait), input abstraction, bitmap font and dialogue box.
  - Scene skeleton: Boot, Title, Lab, Overworld, Battle and End as stubs.
  - The flow state machine, save/load, and `pnpm --filter @latentia/game dev|build|test`.
  - The Playwright smoke test harness.
- **P2: Battle scene v0.** Engine-driven battle UI as specified: intents, move menu, temperature dial, playback, "why" popup, win/lose, 2× speed. Includes placeholder creature rendering, Fable starters included. **Review after P2.**
- **P3: Overworld v0.** The lab, path and trailhead map; movement, collision, interact, sign and NPC; encounter and trainer triggers.
- **P4: Journey and distill.** The whole player journey wired end to end: rival, wild Tokenibble, the Spin up / Graft choice, the card tutorial, the forest trainer, and the end card. Saves at each step.
- **P5: Polish and ship.**
  - Mobile pass: touch targets ≥ 44 CSS px, orientation handling, performance.
  - A README for the game package.
  - Production build. Publish the built game as a **Claude artifact**, a hosted page Travis can open on his phone. GitHub Pages or Vercel come later if he wants.
  - **Final review**, then Travis plays.

## Review Focus
- The engine is used only through its public API, and battle setups always validate.
- Event playback covers every engine event type, with no silent drops.
- Portrait layout on a 390-CSS-px phone: nothing cut off, and the touch controls are usable.
- No softlocks on loss, back navigation, or Continue.
- Determinism isn't the client's job, but the client must not mutate engine state outside `submitRound`.
